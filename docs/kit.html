What this is

Agents that persist lessons across sessions accumulate a corpus of small markdown files. Left alone, that corpus rots: indexes drift from reality, links dangle, names fork, duplicates pile up - and nothing tells you when it happened. This harness treats the corpus as data with invariants and ships the machinery to keep those invariants true.

Memory lives in two stores with different trust surfaces:

operator store

  • Lives outside any repo (for example ~/agent-memory/); personal and cross-project.
  • A flat directory of <slug>.md memories plus three tooling-owned names: MEMORY.md (generated index), HEALTH.md (sweep report), and tmp_* scratch files on a 7-day fuse.
  • Is itself a git repo with a private remote; the sweep commits and pushes snapshots.
  • Checked by the local scheduled sweep - CI cannot see it.

agent store

  • Lives inside the repo at .claude/agent-memory/agent; project-scoped, reviewed through PRs.
  • Holds MEMORY.md (generated index), state.json (tick checkpoint), events/<YYYY-MM-DD>.md (append-only day logs), and lessons/<slug>.md - the durable memories, the only files indexed and health-checked.
  • Gated by path-filtered CI on hard failures.

The guarantees

  • The index cannot drift. MEMORY.md is generated deterministically from file frontmatter by memory-index.sh - a projection of the store, never a hand-maintained document. The gate hard-fails when the committed index differs from regeneration.
  • The gate is falsification-tested. memory-health.sh is read-only by contract, carries a strict exit-code contract, and ships with a mutation matrix (in docs/OPERATIONS.md) that proves every check fires before you trust it.
  • A missing tool never fakes health. Without ripgrep the wikilink checks would return empty result sets - indistinguishable from clean - so the checker dies with exit 2 before running a single check.
  • Exactly one scheduled writer. The sweep's writes are narrow and idempotent: one HEALTH.md overwrite per store plus a snapshot commit. Every possible misfire caps out at a stale report. It notifies only on new findings, never a 48-hour recital of known ones.
  • Names are immutable. The frontmatter name: is the sole link identity; a wrong memory is superseded, never renamed, so no inbound link ever breaks retroactively.
  • Byte-identical everywhere. Every script pins LC_ALL=C, so index output and line-set algebra agree across an interactive macOS shell, launchd, and a Linux CI runner.

Both the health checker and the sweep honour the same contract; the sweep exits with the worst code across both stores, and memory-index.sh exits 2 on fatal errors, 0 otherwise.

A two-store memory harness for coding agents.

Agents that persist lessons across sessions accumulate a corpus of small
markdown files. Left alone, that corpus rots: indexes drift from reality,
links dangle, names fork, duplicates pile up, and nothing tells you when it
happened. This harness treats the corpus as data with invariants and gives
you the machinery to keep those invariants true:

- Two stores. An **operator store** that lives outside any repo (personal,
  cross-project, backed up to a private mirror) and an **agent store** that
  lives inside the repo at `.claude/agent-memory/agent` (project-scoped,

  sanctioned recurring writer: it refreshes a `HEALTH.md` report per store,
  snapshots the operator store to its backup repo, and raises a desktop
  notification only when findings change.

  git repo with a private remote; the sweep commits and pushes snapshots.

## FAQ

**Why a generated index instead of maintaining MEMORY.md by hand?**
A hand-maintained index is a dual-write: every memory change requires a
matching index edit, and the failure mode is silent -- entries orphan, drift
accumulates, and nothing detects it. A derived index cannot drift: it is a
pure function of the corpus, regeneration is idempotent, and the health
check verifies the committed index byte-equals regeneration. The full
argument is in `docs/DESIGN.md`.

**Why does the health check fail closed when ripgrep is missing?**
Because a missing tool must never make a sick store look healthy. Without
`rg`, the wikilink and checkpoint checks would return empty result sets --
zero findings, exit 0 -- on a store full of broken links. Partial results
that cannot be distinguished from clean results are worse than no results,
so the checker dies with exit 2 instead. CI installs ripgrep explicitly for
the same reason: ubuntu runners do not ship it.

**Why `export LC_ALL=C` in every script?**
Sort order is locale-dependent. The same store, indexed from an interactive
macOS shell, a launchd job, and a CI runner, produced differently ordered
output until the collation was pinned -- and index drift between
environments looks exactly like a hygiene failure. Pinning `LC_ALL=C` makes
sort order and line-set algebra byte-identical everywhere.

**Why is a memory never renamed?**
The frontmatter `name` is the sole link identity: wikilinks resolve against
it, and greps for the slug are the dedup check before creating a new memory.
Renaming breaks both -- every inbound link dangles and the lineage forks.
A memory that has become wrong is superseded by a new memory that says so;
the old name keeps resolving forever. Legacy files that diverged before the
rule existed are handled by an empty-by-default grandfather allowlist, not
by renaming (see `docs/DESIGN.md`).

#!/usr/bin/env bash
# scripts/memory-index.sh
# Deterministic MEMORY.md generator for an agent-memory store.
#
# The index is a projection of the store, never a hand-maintained document.
# Regenerating it is idempotent: output is a pure function of the corpus.
# Each entry line is: - [<name>](<relpath>) — <description>
# with name and description taken verbatim from the file's frontmatter.
# A derived index cannot drift the way a hand-maintained dual-write does.
#
# Sort order is metadata.type group (feedback, project, reference), then
# alphabetical by filename. Deliberately NOT recency: mtime is not stable
# across clones and recency is recoverable from git log, while deterministic
# one-line diffs per added memory are not recoverable from a recency sort.
#
# Frontmatter contract (enforced by memory-health.sh, assumed here): exactly
# one single-line `name:` and one single-line `description:` per file, and a
# `type:` line (nested under `metadata:` or top-level) whose value is one of
# feedback|project|reference.
#
# Usage:
#   scripts/memory-index.sh --profile operator|agent <store-root>
#
# Profiles:
#   operator  files are <store-root>/*.md minus MEMORY.md, HEALTH.md, tmp_*
#   agent     files are <store-root>/lessons/*.md
#
# Output goes to stdout. To apply: memory-index.sh ... > <store-root>/MEMORY.md

set -Eeuo pipefail
IFS=$'\n\t'

# Pin collation: the index must be byte-identical no matter which locale the
# invoking shell carries (interactive macOS shell vs launchd vs CI runner);
# an unpinned collation drifts the sort order across locales.
export LC_ALL=C

while [ $# -gt 0 ]; do
  case "$1" in
    --profile) PROFILE="${2:-}"; shift 2 ;;
    -*) die "unknown option: $1" ;;
    *) STORE="$1"; shift ;;
  esac
done
[ -n "$PROFILE" ] && [ -n "$STORE" ] || die "usage: memory-index.sh --profile operator|agent <store-root>"
[ -d "$STORE" ] || die "store root not found: $STORE"

case "$PROFILE" in
  operator)
    list_files() { (cd "$STORE" && ls -- *.md 2>/dev/null) | grep -v -e '^MEMORY\.md$' -e '^HEALTH\.md$' -e '^tmp_' | sort || true; }
    rel() { printf '%s\n' "$1"; }

      cat <<'EOF'
<!-- GENERATED by scripts/memory-index.sh - do not edit by hand.
     Regenerate: scripts/memory-index.sh --profile operator <this-dir> > MEMORY.md
     One line per memory: name and description verbatim from frontmatter.
     Sorted by type group, then filename. -->
EOF
    }
    ;;
  agent)
    list_files() { (cd "$STORE" && ls -- lessons/*.md 2>/dev/null) | sort || true; }
    rel() { printf '%s\n' "$1"; }
    header() {
      cat <<'EOF'
# agent memory index

<!-- GENERATED by scripts/memory-index.sh - do not edit by hand.
     Regenerate: scripts/memory-index.sh --profile agent .claude/agent-memory/agent > MEMORY.md -->

This file is the index for the agent's persistent project memory. It is
loaded automatically into the agent's system prompt on every invocation (first
200 lines). It is an index, not a memory: one line per lesson, name and
description taken verbatim from the lesson frontmatter, sorted by type group
then filename so each new lesson diffs as exactly one line. Recency is
recoverable from git log; deterministic diffs are not recoverable from a
recency sort. CI verifies this file byte-equals regeneration.

Layout under `.claude/agent-memory/agent/`:

- `MEMORY.md` — this generated index.
- `state.json` — tick state (last_tick_iso, tick_count, consecutive_empty_ticks).
- `events/<YYYY-MM-DD>.md` — one file per UTC day, append a section per tick.
- `lessons/<slug>.md` — durable lessons promoted from repeated patterns.

No icons. Anywhere.
EOF
    }
    ;;
  *) die "unknown profile: $PROFILE" ;;
esac

# Frontmatter block only: the lines between the leading '---' delimiters.
# A file not starting with '---' yields empty output (memory-health.sh fails
# it hard). Bounding here keeps a memory free to quote its own template
# (a fenced 'name:' line in the body) without corrupting the index.
fm() { awk 'NR==1{if($0!="---")exit; next} /^---$/{exit} {print}' "$1"; }
fm_field() { # $1=file $2=key -> first single-line value, YAML quotes stripped
  fm "$1" | sed -n "s/^$2: *//p" | head -1 | sed -E 's/^"(.*)"$/\1/; s/^'"'"'(.*)'"'"'$/\1/'
}
fm_type() { # nested metadata.type preferred, top-level tolerated
  fm "$1" | sed -n 's/^[[:space:]]*type: *//p' | head -1
}

header
for want in feedback project reference; do
  section=""
  while IFS= read -r f; do
    [ -n "$f" ] || continue
    t=$(fm_type "$STORE/$f")
    [ "$t" = "$want" ] || continue
    n=$(fm_field "$STORE/$f" name)
    d=$(fm_field "$STORE/$f" description)
    section="${section}- [${n}]($(rel "$f")) — ${d}
"
  done <<EOF
$(list_files)
EOF
  if [ -n "$section" ]; then
    printf '\n## %s\n\n%s' "$want" "$section"
  fi
done

# Design decisions

Every non-obvious decision in this harness, with the failure mode that
motivated it. These are written as portable engineering lessons: each one
was paid for at least once, and each transfers to any system with the same
shape -- small files, links between them, an index, and more than one
environment running the tooling.

## Derived-state index over hand-maintained dual-write

`MEMORY.md` is generated by `scripts/memory-index.sh` from file frontmatter.
It is never edited by hand, and the health gate hard-fails when the
committed index differs from regeneration.

The alternative -- an index maintained alongside the files -- is a
dual-write, and dual-writes have a known failure mode: the two writes are
not atomic, so every add, delete, or description change is an opportunity
to update one side and forget the other. The observable symptom is orphan
rate: index entries pointing at files that no longer exist, and files that
never made it into the index. Orphans accumulate silently because nothing
consumes the index strictly enough to notice.

A derived index eliminates the class rather than policing it. The index is
a pure function of the corpus; regeneration is idempotent; drift is
mechanically detectable (`diff` against regeneration) and mechanically
repairable (regenerate). The general lesson: when state B is a function of
state A, derive B -- do not maintain B and check it against A. Checking is
strictly weaker than deriving; deriving makes the drift impossible.

Sort order is type group, then filename -- deliberately not recency. File
mtimes are not stable across clones, and recency is recoverable from git
log, while the property that each new memory diffs as exactly one line is
not recoverable from a recency sort. Choose sort keys that are stable under
clone and that minimize diff noise.

## Frontmatter name as the sole immutable link identity

Each memory declares a kebab-case `name:` in frontmatter. Wikilinks
(`[[target]]`) resolve against the union of names and filenames sans
extension. The name is immutable for the life of the memory.

Rationale: something has to be the join key, and everything mutable makes a
bad one. Titles get reworded; descriptions get sharpened; dates go stale.
The moment the join key changes, every inbound reference dangles -- and in
a corpus written by an agent across many sessions, nobody is watching the
inbound references. So the identity is a slug, the slug never changes, and
everything mutable lives in fields that nothing links against.

Two corollaries:

- **Supersede, never rename.** A memory whose content became wrong is not
  renamed or rewritten into something else; a new memory is written that
  states the correction, and the old one either points at it or is left as
  historical record. The old name keeps resolving forever, so no link ever
  breaks retroactively. This is the same discipline as never rewriting
  shared git history: identities that others may hold references to are
  append-only.

- **Grandfather allowlist for legacy divergence.** A rule adopted after a
  corpus already exists will have violators that cannot be fixed without
  breaking the rule itself (renaming a legacy file to fix its slug breaks
  its links -- the exact harm the rule exists to prevent). The pattern:
  a shell variable in the checker (`GRANDFATHER`, `GRANDFATHER_DIVERGED`),
  one slug per line, that exempts named legacy files from the check. It
  ships empty: a fresh adoption has no pre-rule history. The critical
  property is that the allowlist is frozen at adoption time -- adding an
  entry for a new file is using the escape hatch as a policy change, which
  the comments in the script explicitly forbid. New violations are fixed;
  old ones are named and tolerated.

## Normalized identity comparison

The name-identity check does not require the frontmatter name to equal the
filename byte-for-byte. Both are first normalized -- type prefix stripped
(`feedback`/`project`/`reference`/`tmp` plus `-` or `_`), underscores
folded to dashes -- and the normalized forms are compared.

Strict basename equality fails on legacy corpora: files created under older
conventions carry type prefixes and underscore separators in the filename
while the frontmatter name uses the clean slug. Those are the same identity
spelled two ways, and flagging them buries the real signal in noise. What
the check must catch is a true lineage fork: a frontmatter name that
denotes a different memory than the filename does, so that a grep for the
slug misses the name and a grep for the name misses the slug -- at which
point the dedup check ("does a memory for this already exist?") silently
answers no and a duplicate lineage is born. Normalization separates the
two cases: spelling variants collapse, forks survive and fail hard.

The same normalization powers the near-miss wikilink check: a link that
resolves only after normalization is a typo at the link site, not an
aspiration, and is failed hard with a suggestion -- fix the link, not the
file.

## Fail-closed toolchain preflight

`memory-health.sh` dies (exit 2) if ripgrep is not on PATH, before running
a single check.

The trap this closes: the wikilink and checkpoint checks are built on `rg`.
If `rg` is missing and the failure is soft, those checks return empty
result sets -- which is indistinguishable from "no broken links". A sick
store reports healthy, and it reports healthy precisely in the environments
most likely to be missing the tool: fresh CI runners (ubuntu images do not
ship ripgrep) and scheduler contexts with a bare PATH. A gate that can be
silently disarmed by its own environment is not a gate.

The general rule: when a checker's dependencies are absent, the checker
must report "cannot check" as a failure, never "nothing found". The CI
workflow installs ripgrep explicitly, and the scripts prepend the common
local bin directories to PATH for scheduler contexts -- but those are
conveniences; the preflight remains the authority.

## Collation pinning

Every script exports `LC_ALL=C` before doing anything else.

The failure this fixes: `sort` order is locale-dependent, and the harness
runs under at least three locales -- an interactive macOS shell (typically
a UTF-8 locale), launchd (bare environment), and a Linux CI runner. An
unpinned collation produced index output whose sort order drifted across
those environments: the same store regenerated on two machines gave two
byte-different indexes, and the health gate's drift check -- correctly --
failed, blaming the store for a property of the environment. The line-set
algebra in the checker (`sort -u`, `uniq`, `grep -x` against sorted files)
has the same sensitivity.

Lesson: any script whose output is compared byte-for-byte across
environments, or that feeds `sort` output into set operations, must pin its
collation. `LC_ALL=C` is the only portable pin.

## Delimiter-bounded frontmatter parsing

Frontmatter is extracted by an awk program that takes only the lines
between the leading `---` delimiter pair, and nothing else:

    awk 'NR==1{if($0!="---")exit; next} /^---$/{exit} {print}'

The naive alternative -- grepping the whole file for `^name:` -- has a
self-referential failure mode: a memory that documents the memory template
(this harness ships one in `templates/memory-template.md`) quotes `name:`
and `description:` lines in its body. Whole-file grep counts those quoted
lines as real keys and fails the file for duplicate frontmatter -- the
store's own documentation trips the gate. Bounding the parse at the
closing delimiter makes body content, fenced or not, invisible to the
checker and the index generator alike.

The bound also fails safe in the other direction: a file that does not
start with `---` yields empty frontmatter, so the exactly-one-key check
fails it hard rather than half-parsing it.

The parser is deliberately not a YAML library: the contract is single-line
scalar values only, enforced by the gate, and bash 3.2 + awk covers that.
The flip triggers are written in the script header: adopt a real parser
the day frontmatter needs nesting beyond single-line scalars, a health run
exceeds 5 seconds, or a store crosses 2000 files.

## Single sanctioned writer, notify-on-change

Exactly one scheduled process is allowed to write anything:
`memory-health-sweep.sh`. Its writes are narrow and idempotent -- one
`HEALTH.md` overwrite per store, plus a snapshot commit of the operator
store's backup repo (empty diff commits nothing). The health checker
itself is read-only by contract; the index generator writes only to stdout.

Why: recurring automation that mutates state is where unattended damage
compounds. A scheduled job that "helpfully" regenerates indexes or edits
memories will eventually do so against a store mid-edit, or after a path
moved, and each firing compounds the damage. Confining all scheduled
writes to one auditable script with an append-only output (report file,
snapshot history) caps the blast radius of every misfire at "a stale
report".

Notification discipline: the sweep raises a desktop notification only when
the report differs from the previous sweep AND carries failures or
warnings. A recurring notifier that re-announces known findings every fire
trains its operator to ignore it within a week; new-findings-only keeps
the signal alive. On systems without a notifier the exit code still
carries the result.

## Gate self-coverage in the CI path filter

The CI workflow is path-filtered so feature PRs never pay for it, but the
filter includes not just the store (`.claude/agent-memory/**`) but the
three scripts and the workflow file itself.

A gate whose own implementation can change without the gate running is a
gate that can be broken -- or quietly disarmed -- by the very PR that
breaks it. Including the tooling and workflow paths in the filter means
any PR that touches the checker, the generator, the sweep, or the gate
definition must pass the gate it just modified. Cheap, and it converts
"the gate was silently broken three weeks ago" into "this PR is red".

## The dead-man gap (known limit)

The scheduled sweep has a dead-man problem this harness documents rather
than solves: if the sweep stops firing -- the repo the scheduler points at
was moved or deleted, the checked-out branch no longer contains the
scripts, the plist was unloaded, the machine was replaced -- nothing
notices. The notification path only fires on new findings, so silence is
indistinguishable from health.

Recommended mitigations, in preference order:

- **Dedicated stable clone for the scheduler.** Point the scheduler at a
  clone used for nothing else, pinned to the default branch, at a path
  that never moves. This removes the dominant failure cause (the working
  clone being moved, rebased, or checked out to an old branch under the
  scheduler's feet).

- **Session-start freshness check.** The sweep stamps its generation time
  on the first line of each `HEALTH.md`. An agent session-start hook (or a
  shell profile line) that compares that stamp against the sweep interval
  and warns when it is older than two intervals converts silent scheduler
  death into a visible nag exactly where the operator is looking.

Both mitigations are deployment choices, not shipped code -- which
scheduler, which clone, and which session hook are all adopter-specific.
The limit itself is the portable lesson: any cron-shaped safety net needs
either a heartbeat consumer or a freshness check at the point of use,
because the failure mode of a scheduler is silence.

## Install runbook

### Prerequisites (both platforms)

- bash 3.2 or newer (macOS system bash is enough by design).
- ripgrep (`rg`) on PATH. The health checker fails closed without it.
  macOS: `brew install ripgrep`. Debian/Ubuntu: `apt-get install ripgrep`.
- The three scripts under `$REPO/scripts/`, executable
  (`chmod +x scripts/memory-*.sh`).
- Both stores initialized and indexed (see the README quickstart), and a
  clean baseline run: `memory-health.sh` exits 0 or 1 on each store.

### macOS (launchd)

1. Copy `templates/launchd.plist.template` and replace every
   `__PLACEHOLDER__` token:

   - `__LABEL__` -- reverse-DNS job label, e.g. `com.example.memory-health`.
     Must match the installed plist filename sans `.plist`.
   - `__REPO_ROOT__` -- absolute path to `$REPO`.
   - `__OPERATOR_STORE__` -- absolute path to the operator store; the sweep
     refuses to run without `MEMORY_SWEEP_OPERATOR_STORE`.
   - `__LOG_PATH__` -- absolute path to a writable log file, e.g. the
     expansion of `~/Library/Logs/memory-health-sweep.log`.

2. Install and load:

       cp filled-in.plist ~/Library/LaunchAgents/__LABEL__.plist
       launchctl load ~/Library/LaunchAgents/__LABEL__.plist

3. Verify: `launchctl list | grep __LABEL__` shows the job. The template
   sets `StartInterval` 172800 (every 2 days) and `RunAtLoad` false, so
   loading does not fire an immediate sweep -- run
   `scripts/memory-health-sweep.sh` by hand once to confirm the wiring and
   seed the first `HEALTH.md` in each store.

### Linux (systemd user units)

1. Copy both templates and replace `__REPO_ROOT__` and
   `__OPERATOR_STORE__`:

       cp templates/systemd-user.service.template \
          ~/.config/systemd/user/memory-health-sweep.service
       cp templates/systemd-user.timer.template \
          ~/.config/systemd/user/memory-health-sweep.timer

2. Enable:

       systemctl --user daemon-reload
       systemctl --user enable --now memory-health-sweep.timer

3. Verify: `systemctl --user list-timers` shows the timer;
   `journalctl --user -u memory-health-sweep.service` shows run output.
   The timer fires 15 minutes after boot, then every 2 days;
   `Persistent=true` fires a missed run at the next login instead of
   silently skipping it.

On either platform, prefer pointing the scheduler at a dedicated stable
clone rather than your working clone -- see the dead-man section of
`docs/DESIGN.md` for why.

## Mirror-backup flow

The operator store lives outside any project repo, so nothing backs it up
unless you make it a repo of its own.

1. Create an empty private repository on your git host (no README, no
   initial commit -- the store's history starts locally).

2. Initialize the store as a repo on branch `main` (the sweep pushes
   `origin main` specifically) and connect it:

       cd "$OPERATOR_STORE"
       git init -b main
       git add -A
       git commit -m "Initial memory snapshot"
       git remote add origin <private-repo-url>
       git push -u origin main

3. From then on, every sweep run: stages everything (`git add -A`), commits
   only when the staged diff is non-empty, with the message
   `Scheduled memory snapshot (YYYY-MM-DD)`, and pushes to `origin main`
   when an `origin` remote exists. Commit identity comes from
   `MEMORY_SWEEP_GIT_NAME`/`MEMORY_SWEEP_GIT_EMAIL` when both are set,
   otherwise from the store's own git config.

Lost-remote behavior:

- No `origin` configured: the push is skipped quietly. Snapshots still
  accumulate as local commits, so wiring a remote later pushes the full
  accumulated history in one go.
- `origin` configured but unreachable or deleted: the push fails, the
  sweep appends `backup push failed` to its notification lines and keeps
  going. Nothing is lost -- history is local-first. Repair the remote (or
  create a fresh private repo and repoint `origin`), then either wait for
  the next sweep or push by hand.

## Falsification test recipe

Never trust a gate you have not watched fire. This recipe seeds one defect
per hard check into a disposable fixture store and states the expected
`FAIL` line and exit code for each. Run it once at adoption, and again
after any change to `memory-health.sh`.

Ground rules:

- Work only on the fixture, never on a real store.
- After each mutation: run the checker, confirm the expected line appears
  and `echo $?` prints the expected code, then restore the fixture (the
  simplest restore is to rebuild it from step 1).
- A seeded frontmatter defect usually also trips `index drift`, because
  the index derives from frontmatter. That collateral finding is correct
  behavior; assert the target line is present, not that it is alone.

### Fixture setup (operator profile)

    STORE=$(mktemp -d)
    cat > "$STORE/first-lesson.md" <<'EOF'
    ---
    name: first-lesson
    description: First fixture memory for the falsification run.
    metadata:
      type: reference
    ---
    Fixture body. Related: [[second-lesson]].
    EOF
    cat > "$STORE/second-lesson.md" <<'EOF'
    ---
    name: second-lesson
    description: Second fixture memory for the falsification run.
    metadata:
      type: project
    ---
    Fixture body.
    EOF
    scripts/memory-index.sh --profile operator "$STORE" > "$STORE/MEMORY.md"
    scripts/memory-health.sh --profile operator "$STORE"

Baseline expectation: `== result: 0 hard failure(s), 0 warning(s) ==`,
exit 0. Do not proceed until the baseline is clean.

### Mutation matrix (hard checks, expected exit 2)

Missing index. Seed: `rm "$STORE/MEMORY.md"`. Expect:
`FAIL  no MEMORY.md index in $STORE`.
Restore: regenerate the index.

Index drift. Seed: `echo extra >> "$STORE/MEMORY.md"`. Expect:
`FAIL  index drift: MEMORY.md differs from regeneration (run: ...)`
followed by an indented diff excerpt.
Restore: regenerate the index.

Dangling index pointer. Seed: append a fake entry,
`echo '- [ghost](ghost.md) — gone' >> "$STORE/MEMORY.md"`. Expect:
`FAIL  dangling index pointer: ghost.md` (plus index drift).
Restore: regenerate the index.

Index generator failure. Seed: `chmod -x scripts/memory-index.sh`.
Expect: `FAIL  index generator failed for $STORE`.
Restore: `chmod +x scripts/memory-index.sh`.

Missing frontmatter key. Seed: delete the `description:` line from
`first-lesson.md`. Expect:
`FAIL  frontmatter: first-lesson.md has 0 'description:' lines (want exactly 1)`.
The same check reports 2 lines if you duplicate the key instead.
Restore fixture.

Empty name. Seed: change the name line to `name:` (no value). Expect:
`FAIL  frontmatter: first-lesson.md has 'name:' with an empty value - nameless memories index as broken links`
(plus a collateral key-count failure: a bare `name:` no longer matches
the `name: ` key pattern, so the exactly-one check reports 0 lines).
Restore fixture.

Non-slug name. Seed: set `name: First Lesson Prose Title`. Expect:
`FAIL  name is not a kebab slug: first-lesson.md has name 'First Lesson Prose Title' - ...`.
Restore fixture.

Name-identity divergence. Seed: set `name: totally-different-slug` in

`FAIL  name-identity divergence: first-lesson.md has name 'totally-different-slug' - a diverged name forks the dedup lineage: ...`.
Restore fixture.

Missing type. Seed: delete the `type:` line. Expect:
`FAIL  frontmatter: first-lesson.md has no type`.
Restore fixture.

Type fragmentation. Seed: set `type: lesson`. Expect:
`FAIL  type fragmentation: first-lesson.md has type 'lesson' (want feedback|project|reference)`.
Restore fixture.

Byte duplicates. Seed:
`cp "$STORE/first-lesson.md" "$STORE/copied-lesson.md"`. Expect:
`FAIL  byte-duplicate files: copied-lesson.md first-lesson.md` (order per
sort; collateral name-identity and index-drift findings also fire, since
the copy carries the original's name).
Restore: `rm "$STORE/copied-lesson.md"`; regenerate the index.

Near-miss wikilink. Seed: append `See [[first_lesson]].` to the body of
`second-lesson.md` (underscore where the slug has a dash). Expect:
`FAIL  near-miss wikilink: [[first_lesson]] in second-lesson.md - did you mean: first-lesson`.
Restore fixture.

Aspirational wikilink, escalated. Seed: append `[[missing-target]]` to the
body of both fixture files. Expect:
`FAIL  aspirational wikilink in 2 files: [[missing-target]] - two files rely on a memory that does not exist; write it or fix the links`.
With the link in only one file, expect instead
`WARN  aspirational wikilink: [[missing-target]] (allowed while single-referenced)`
and exit 1.
Restore fixture.

Expired tmp scratch (operator profile only). Seed:

    touch "$STORE/tmp_probe.md"
    # macOS:
    touch -mt "$(date -v-8d +%Y%m%d%H%M)" "$STORE/tmp_probe.md"
    # Linux:
    touch -d '8 days ago' "$STORE/tmp_probe.md"

Expect: `FAIL  expired tmp scratch (>7 days): tmp_probe.md - promote to a memory or delete`.
With a fresh mtime instead, expect
`WARN  tmp scratch present: tmp_probe.md (7-day fuse; ...)` and exit 1.
Restore: `rm "$STORE/tmp_probe.md"`.

Checkpoint behind log (agent profile only). Seed a minimal agent fixture:

    ASTORE=$(mktemp -d)
    mkdir -p "$ASTORE/lessons" "$ASTORE/events"
    cp "$STORE/second-lesson.md" "$ASTORE/lessons/second-lesson.md"
    scripts/memory-index.sh --profile agent "$ASTORE" > "$ASTORE/MEMORY.md"

Expect:
`FAIL  checkpoint behind log: state.json last_tick_iso=2024-01-01T00:00:00Z < newest event stamp 2024-01-02T10:00:00Z`.
Setting `last_tick_iso` to `2024-01-02T10:00:00Z` or later flips it to

installed. Expect on stderr:
`memory-health: FATAL: ripgrep (rg) not found on PATH - ...`,
exit 2, and no check output at all -- proving a missing tool cannot
produce a clean-looking report.

- Date-bearing slug: create `note-2024-01-01.md` with valid frontmatter

  kebab slug, and matching the filename avoids a collateral divergence
  failure), regenerate the index, and expect
  `WARN  date-bearing slug: note-2024-01-01.md (mutable data in an immutable identity; frontmatter holds dates)`.

## Troubleshooting

**`memory-health: FATAL: ripgrep (rg) not found on PATH`.**
This is the fail-closed preflight, not a bug: the wikilink and checkpoint
checks depend on `rg`, and partial results must not report a store as
healthy. Install ripgrep. In scheduler contexts note that launchd and CI
runners start with a bare PATH; the scripts prepend `/opt/homebrew/bin`
and `/usr/local/bin` themselves, so if your `rg` lives elsewhere, extend
`PATH` in the scheduler unit or workflow. The shipped CI workflow installs
ripgrep explicitly because ubuntu runners do not ship it.

**Index drift failures that only reproduce on one machine or in CI.**
Classic locale-drift symptom: the diff excerpt shows the same entries in a
different order, none added or removed. The shipped scripts pin
`export LC_ALL=C`, so a committed index generated by them cannot drift
this way -- the stale side is a `MEMORY.md` that was generated by an older
unpinned script or sorted by hand. Regenerate with the shipped generator
and commit the result. If drift persists, diff the two environments'
`sort` behavior directly with slug-shaped input --
`printf 'a_b\na-b\nab\n' | sort` -- dashes and underscores are exactly
where UTF-8 collations disagree with C, and memory slugs are full of
both. Both environments must give the C order.

**Sweeps stopped happening / HEALTH.md is stale.**
Check the generation stamp on the first line of each store's `HEALTH.md`;
older than two sweep intervals means the scheduler is not firing or the
sweep is dying early. Usual cause: the scheduler points at a moved or
deleted path -- the repo was relocated, or the checked-out branch no
longer contains `scripts/`. Diagnose on macOS via the `__LOG_PATH__` log
file and `launchctl list __LABEL__` (a non-zero last-exit status), on
Linux via `journalctl --user -u memory-health-sweep.service`. Fix the
path in the plist or unit (reload it afterwards), or better, point the
scheduler at a dedicated stable clone as recommended in `docs/DESIGN.md`.
Remember the sweep also exits 2 immediately when
`MEMORY_SWEEP_OPERATOR_STORE` is unset -- an edited unit that dropped the
environment block produces exactly this symptom.

**`backup push failed` in the sweep notification.**
The snapshot commit succeeded locally; only the push to `origin main`
failed. Check `git -C "$OPERATOR_STORE" remote -v` and push by hand to see
the real error (auth expired, repo deleted, offline). Nothing is lost --
see the lost-remote behavior above.

rationale

Why it is built this way

Every guarantee above traces to a section of the embedded docs/DESIGN.md, and every section there was paid for at least once. The map, in one pass:

  • Derived-state index over hand-maintained dual-write - when state B is a function of state A, derive B; do not maintain B and check it against A. Checking is strictly weaker than deriving; deriving makes the drift impossible.
  • Frontmatter name as the sole immutable link identity - everything mutable makes a bad join key. Supersede, never rename; the grandfather allowlists ship empty and are frozen at adoption time.
  • Normalized identity comparison - spelling variants (type prefixes, underscores) collapse; true lineage forks survive normalization and fail hard. The same normalization turns a near-miss wikilink into a hard failure with a suggestion.
  • Fail-closed toolchain preflight - when a checker's dependencies are absent it must report cannot check as a failure, never nothing found. A gate that can be silently disarmed by its own environment is not a gate.
  • Collation pinning - any script whose output is compared byte-for-byte across environments must pin LC_ALL=C; index drift between locales looks exactly like a hygiene failure.
  • Delimiter-bounded frontmatter parsing - the parse stops at the closing ---, so a memory that quotes name: lines in its body (the shipped template does) cannot trip the gate or corrupt the index.
  • Single sanctioned writer, notify-on-change - recurring automation that mutates state is where unattended damage compounds; confining scheduled writes to one auditable script caps every misfire at a stale report, and new-findings-only notification keeps the signal alive.
  • Gate self-coverage in the CI path filter - the filter includes the checker, the generator, the sweep, and the workflow itself, so any PR that touches the gate must pass the gate it just modified.
  • The dead-man gap - the one documented, unsolved limit: a scheduler's failure mode is silence. Mitigations (a dedicated stable clone; a session-start freshness check against the HEALTH.md stamp) are deployment choices, spelled out in the doc.

The full argument for each, with the concrete failure that motivated it, is in docs/DESIGN.md above - part of the kit, so the reasoning travels with the code.
