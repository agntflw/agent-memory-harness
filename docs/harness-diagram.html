Memory Harness

How agent memory persists, indexes, and defends itself: two stores, one derived index, one read-only health gate, and three enforcement surfaces — plus the one gap the harness currently has, drawn honestly.

Figure 1

The write–read loop

Sessions append memories to the stores; scripts/memory-index.sh projects frontmatter into MEMORY.md; the index is what loads back into agent context at the next session start. The index is derived, never authored — the one failure this system has actually had was a hand edit of MEMORY.md, a dual write that orphaned entries.

Operator store

~/.claude/projects/<proj>/memory/

  • A git repo of its own, outside the project repo — snapshot history plus a private remote backup.
  • One markdown file per memory; frontmatter carries name / description / type (feedback | project | reference).
  • The name is the immutable identity: kebab-case, filename == name, never renamed — superseded instead.

In-repo agent store

.claude/agent-memory/<agent>/

  • lessons/ holds the indexed memories; same frontmatter contract.
  • events/ and state.json stay gitignored — workstation-local run state, invisible to CI.
  • Its MEMORY.md carries a 200-line prompt-load budget (warned at 190).

The gate

memory-health.sh, the read-only checker

One script audits a store and never mutates anything. Its exit code is the contract every enforcement surface builds on. It fails closed — exit 2 — when ripgrep is missing, and pins LC_ALL=C so reports and regenerated indexes are byte-identical across the interactive shell, launchd, and the CI runner.

0clean

No findings, or informational only.

1warnings

Reported, never blocking — surfaced by the sweep.

2hard failure

Any check below. The only code CI blocks on.

  • index driftMEMORY.md differs from a fresh regeneration
  • dangling index pointerindex entry whose file does not exist
  • frontmatter keysname / description / type missing or duplicated
  • non-slug namename not kebab-case — the name is the link identity
  • empty namename: present with an empty value
  • name-identity splitnormalized basename diverges from normalized name
  • type fragmentationtype outside feedback | project | reference
  • byte duplicatestwo files with identical content
  • near-miss wikilink[[target]] that resolves only after slug normalization — a typo, fixed at the link site
  • expired tmp scratchtmp_* older than 7 days (operator profile)
  • checkpoint behindstate.json last_tick_iso older than the newest event (agent profile)

Warnings (exit 1): aspirational wikilinks (escalating to hard once two files want the same target), tmp scratch present, index over line budget, date-bearing slugs, and cross-store [[operator:x]] / [[agent:x]] links that fail to resolve when --also-resolve is given.

Figure 2

Enforcement: three surfaces, one writer

Both lanes converge on the same checker. CI can only see the in-repo store, so it gates hard failures on PRs; the launchd sweep is the only surface that sees both stores — and it is the single sanctioned scheduled writer, producing HEALTH.md, the notification, and the mirror push.

CI gate

.github/workflows/memory-health.yml

  • Fires only on PRs touching the in-repo store, the memory-*.sh tooling, or the workflow file itself.
  • Installs ripgrep, then gates on exit 2 only — warnings never block a merge.
  • Cannot see the operator store or gitignored events/; cross-store links report as informational here.

Launchd sweep

com.example.memory-health.plist

  • Every 2 days (StartInterval 172800) runs memory-health-sweep.sh over both stores with cross-store link resolution.
  • Writes one idempotent HEALTH.md per store; notification fires only when a report with findings changed since the last sweep.
  • The only complete health surface — nothing else sees both stores.

Mirror push

operator store → private mirror repo

  • The same sweep is the single sanctioned scheduled writer: it stages the operator store, snapshot-commits, and pushes over SSH.
  • Append-only history, no PRs, no shared branches; an empty diff commits nothing.
  • Works agentless from a scheduler context — no ssh-agent required.

Known gap — the sweep dies with the working tree

The launchd job executes scripts/memory-health-sweep.sh from the main working tree of the project repo. When that tree is checked out on a branch that does not carry the memory scripts, the job either fails to exec or exits 2 at its own [ -x memory-health.sh ] guard — and the failure lands only in a log file. No notification, no CI signal, nothing watches the watcher.
